Use the **myflow-research** skill — installed globally, so let your harness resolve it by name rather than assuming a project-local path.

Follow that skill exactly. A stance, not a workflow: investigate, ask, and visualize — never write application code, never advance pipeline state, never commit.

**Input:** the argument after `/myflow-research` is whatever the user wants to think about — a vague idea, a specific problem, a change id (to explore in context of that change), a comparison, or nothing at all. Pass it through as the topic.

**When done:** there's no required next step. If the thinking is ready to become a change, run `/myflow-start`.
