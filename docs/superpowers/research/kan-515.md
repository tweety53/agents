# Mockup frame geometry, three-panel diff and size gate in compose-mockup-frames — research notes

Source: KAN-515

The agents-repo half of KAN-514, whose gymie-side note is
`gymie/docs/superpowers/research/kan-514.md`. This change lands first: the gymie plan's
`mockup frame` row and its composites need the crop, the diff panel and the size gate this note
designs.

## 1. What the mockups actually are

The 34 PNGs under `gymie/docs/design/mockups/` (the same files as
`docs/design/group-sessions/screens/`, plus `J1-pre-exits.png` and `J5a.png`) are 2x exports of
the phone frames in `docs/design/group-sessions/design/Gymie Group Session Flow.html`. The HTML is
the source, confirmed by the operator; every frame is the same markup:

- a container `width:390px; min-height:748px; border:1px solid; border-radius:4px;
  box-sizing:border-box; overflow:hidden; display:grid; grid-template-rows:auto auto 1fr auto`;
- row 1, a **26px status line** (`17:43` · `5G · 82%`) the web app never renders;
- row 2, a **52px wordmark bar** — the same 52dp the app's own bar has since KAN-175;
- content that hugs its height, so frames run from 520 to 1330 logical px tall;
- a dark (42, 42, 42) **caption band** under every frame, of varying height, carrying the design
  doc's annotation text.

Measured on the PNGs (Pillow, `G1.png`): 780 wide; border pixels at columns 0–1 and 778–779 and
rows 0–1; status line rows 2–53; the app bar starts at row 54; frame bottom border at rows
1494–1495; caption from row 1496. So the **content area is 776 × (frame − 4 − 52) px, i.e. 388 ×
(frame/2 − 2 − 26) logical**, and the app must be captured at **388 wide**, not 390 — the 1px
border is inside the 390 (`border-box`).

The existing compose step (`scripts/compose-mockup-frames.py`, symlinked from
`skills/flow/scripts/`) pastes both PNGs at native size with a 16px gutter and no cropping, so
every composite so far compared a 1200×1164 desktop capture against a 780×2028 phone frame with
its status line and caption — the "never apples-to-apples" root cause KAN-514 records.

## 2. Declared geometry, detected caption

The operator chose declared rows over pixel heuristics for the fixed part of the geometry. One new
optional setting in `## visual verification`, closed vocabulary extended by one name:

| Setting | Value shape | gymie's value |
|---|---|---|
| `mockup frame` | `scale=<int> status=<logical px> border=<logical px>` | `scale=2 status=26 border=1` |

Crop, in PNG pixels with `s = scale`: left `border·s`, top `(border + status)·s`, right
`w − border·s`, bottom `frame_bottom − border·s`, where **`frame_bottom` is detected, not
declared**, because it differs per frame: the page background is the pixel at (0, 0) — outside
the rounded corner, so always the page, never the frame — and `frame_bottom` is the first row
below the top crop whose every pixel in `[border·s, w − border·s)` equals it; no such row means
the frame runs to the image's last row. A uniform row is what the caption band's own top margin
guarantees, and no screen row is uniformly the page colour edge to edge because the border sits
inside it. `ponytail:` a screen drawn entirely in the page colour with no border would stop the
scan early; the border makes that impossible for this package and a project without one declares
`border=0` and gets no detection past a uniform row.

**No row declared → today's behaviour unchanged**: no crop, two panels, and the size gate off,
so every other project's composites and the 19 existing harness cases keep their meaning.

## 3. Three panels and a ratio

Composite layout with the row declared: capture | cropped frame | diff, same 16px gutter, same
(40, 40, 40) background, top-aligned, no labels, no scaling. The diff panel is
`ImageChops.difference(capture, frame).convert("L").point(lambda v: 255 if v else 0)` rendered as
white-on-black, so a departure reads as shape, not as a colour blend. The ratio is differing pixels
over total pixels, printed to four decimals.

stdout becomes `<composite path> diff=<ratio>` per line (`diff=n/a` when no row is declared and
the two-panel composite was written). Nothing parses that stdout — `flow.visual-verify` step 9
hands it to the verifier to read — so the shape change costs one contract sentence. kan-486's
`no-pixel-diff` decision stands: the ratio is information the verifier reads beside the panels,
never a threshold that blocks. The operator confirmed this: three panels plus ratio, no gate.

## 4. Size mismatch is a finding

With the row declared, a capture whose size differs from the cropped frame is
`<map>:<line>: capture <w>×<h> vs frame <w>×<h> for <frame id>` on stderr and exit 1, exactly
the class of "broken map" the existing exit-1 findings already are — the pair is skipped, every
other line still composes. This is what makes the comparison apples-to-apples by construction:
a spec that set the wrong viewport height blocks instead of producing a composite that reads as
a layout departure. The operator chose blocking over a warning.

## Step-by-step breakdown

### Geometry crop in compose-mockup-frames.py

**What:** An optional fourth argument `scale=<n> status=<px> border=<px>`; with it, each frame is
cropped to its content area, the bottom found by the uniform-page-row scan of section 2.
**Why:** The status line, border and caption are HTML chrome the app never renders; composing
them guaranteed a false departure on every pair.
**Uses:** `scripts/compose-mockup-frames.py`, Pillow.

### Three-panel composite with a diff ratio

**What:** capture | cropped frame | binary difference panel; stdout `<path> diff=<ratio>`.
**Why:** "A real side-by-side diff" (KAN-514's title): a verifier reading two panels by eye missed
padding, shadow and colour departures across four fix rounds of kan-30.
**Uses:** `scripts/compose-mockup-frames.py`, `PIL.ImageChops`.

### Size-mismatch finding

**What:** With the geometry declared, a capture not equal in size to the cropped frame is a
finding line and exit 1 for that map line.
**Why:** Equal size is the whole apples-to-apples guarantee; a wrong viewport must block, not
compose.
**Uses:** `scripts/compose-mockup-frames.py`, `flow.visual-verify`'s **Blocking** list.

### The `mockup frame` setting

**What:** One optional row in `## visual verification`, value `scale=<int> status=<px>
border=<px>`, validated by the section guard.
**Why:** The operator chose declared geometry over heuristics for the fixed part; the guard's
vocabulary is closed, so the name must be added there or the row is dropped.
**Uses:** `skills/flow-contracts/project-configuration.md`, `scripts/check-visual-verification.sh`,
`scripts/test-check-visual-verification.sh`.

### Stage step 9 wiring

**What:** The verifier prompt carries the resolved row; the compose command passes it; the stdout
shape sentence changes.
**Why:** The stage owns its procedure; nothing else restates the compose command.
**Uses:** `skills/flow/verify-and-handoff.md`.

### Harness cases

**What:** New cases in `test-compose-mockup-frames.sh` for crop, detection, mismatch, ratio and
the no-row path.
**Why:** The harness is the only runnable check of the script's exit codes and layout.
**Uses:** `scripts/test-compose-mockup-frames.sh`.
