# Flow context thinning — research notes

Source: KAN-378 (change 1); KAN-379 (change 2)

## 1. Measurement — what a `/flow` run actually loads (at `main`, post kan-372)

kan-372 (merged at `63cb3b6`) made the router's contract loads lazy and reported a creating run at
128k bytes "after". That figure counted phase files only. Followed to the leaf — every contract a
phase file now loads at its point of use, plus the superpowers skills each phase invokes — the
parent session of a creating run still loads roughly the following before it reads a line of
project code. Bytes measured with `wc -c`; tokens approximated at bytes ÷ 4.

| Layer | Files | bytes | ~tok |
|---|---|---|---|
| Always-on | `~/.claude/CLAUDE.md` 14.2k, project `CLAUDE.md` 10.4k, `rules/agent-baseline.md` 5.5k | 30k | 7.5k |
| Router | `skills/flow/SKILL.md` 15.7k, `skills/flow-contracts/pipeline.md` 28.6k | 44k | 11k |
| Brainstorm, parent side | `brainstorm.md` 29k (parent needs ~10k; sections B–D, ~19k, are the planner's), `jira-integration.md` 16k | 45k | 11k |
| Implement | `implement.md` 18.5k, `artifacts-registry.md` 6.8k, `worktree-resolution.md` 1.9k, `workspace-isolation.md` 25k | 52k | 13k |
| Review panel | `review-panel.md` 35.9k, `project-configuration.md` 44.7k | 81k | 20k |
| Verify / handoff | `verify-and-handoff.md` 21.4k, `git-boundaries.md` 5.8k, `session-records.md` 1.9k | 29k | 7k |
| Superpowers invoked in-session | subagent-driven-development 52k, brainstorming 30k, writing-plans 8.7k, requesting-code-review 8.6k, using-git-worktrees 6.8k | 106k | 27k |
| **Total instruction text, creating run** | | **~387k** | **~97k** |

Per subagent dispatch, before its role prompt: global `CLAUDE.md` 14.2k + project `CLAUDE.md`
10.4k + `MEMORY.md` 2k (all harness-injected) + the mandated `agent-baseline.md` read 5.5k =
**~32k bytes / ~8k tokens**, in each subagent's own prompt cache. A five-slot panel round spends
~40k tokens on that alone; each per-task combined reviewer and each implementer adds another 8k.

Role-specific loads on top:

- Planner: `brainstorm.md` B–D 19k + superpowers:brainstorming 30k + writing-plans 8.7k +
  `plan-provenance.md` 25k + `build-green.md` 5.3k ≈ 88k bytes (~22k tok).
- Principles slot: `principles-reviewer-prompt.md` 10.3k + `engineering-principles.md` 9k +
  `project-configuration.md` 44.7k (cited at `principles-reviewer-prompt.md:176` for the
  `## standards` containment rule, although the parent has already resolved `[STANDARDS_PATHS]`
  before dispatch) ≈ 64k.
- Implementer: the dispatch bundle (proposal, design, tasks, engineering principles) +
  superpowers:test-driven-development 17k, plus systematic-debugging 33k when triggered. The
  bundle already carries `engineering-principles.md`; the `REQUIRED READING` paragraph makes the
  implementer read it a second time.

`scripts/check-contract-budget.sh` is a ratchet against regrowth (+25% of each file's landed size);
it holds a cut but never drives one.

## 2. Parent session — what is loaded but not acted on, and what is restated

Deletion-only findings (no behaviour change):

- `skills/flow/SKILL.md` **Stage keys** (~3.5k) states that `stats/internal/stages/names.go`
  "does not yet list any `flow.*` key" and that `/flow` "is not yet a row" in `pipeline.md`'s
  table. `names.go` carries 30 `flow.*` keys and a `Flow` command constant today. The whole
  disclosure, and the "`model-policy.md` is only partly current" caveat paragraph (~1k), are
  stale text loaded on every invocation.
- Rationale in run-loaded files despite the `-rationale.md` convention: lines matching
  "this task / was rejected / design.md's / the alternative / known gap" — 13 in `SKILL.md`,
  16 in `brainstorm.md`, 10 in `integrate.md`, 15 each in `finish-contract-run1.md` and
  `jira-integration.md`, 11 each in `finish-contract-run2.md` and `workspace-isolation.md`,
  9 in `project-configuration.md`. Rejected-alternative reasons move to the file's
  `-rationale.md` sibling; they are never deleted.
- The state-transition table appears four times in one creating run: the global `CLAUDE.md` flow
  stub, project `CLAUDE.md`'s **/flow commands summary** (4.2k), `SKILL.md`'s **State
  transitions**, and `pipeline.md`'s. Keep two: the global stub (present before any load) and
  `pipeline.md` (canonical).
- `brainstorm.md` is read in full by the parent (needs section A + **Dispatch the planner**,
  ~10k) and again by the planner (needs B–D, ~19k). Split into two files, each read once.
- `superpowers:subagent-driven-development` (52k) is invoked once, at `implement.md:217`;
  `implement.md` overrides its parallel-dispatch guidance and fully specifies the implementer
  prompt itself. Drop the invocation.

Mechanics-to-code findings (behaviour moves into `flow`/scripts, needs tests):

- `project-configuration.md` (44.7k) is loaded by `review-panel.md` (one key:
  `## review panel citation check`), `verify-and-handoff.md` (`## lint`, `## test`),
  `implement.md`, `integrate.md`, `archive.md` (`## remove`) and the principles slot
  (`## standards`). It is a set of resolution rules written as prose; only a script needs the
  rules. Thirty-plus scripts already parse `.flow/project.md` sections
  (`gather-dispatch-context.sh`, `prepare-workspace.sh`, `check-visual-trigger.sh`, …), so a
  `flow project get <section>` subcommand or `scripts/project-get.sh` returning the resolved
  value is a wrapper over existing parsing, not new logic. kan-372 already did exactly this for
  `## lint`/`## test`/`## run` inside the dispatch bundle.
- `workspace-isolation.md` (25k) is applied end to end by `prepare-workspace.sh`; `implement.md`
  step 2 still loads the prose. Load it only when the script exits nonzero.
- `plan-provenance.md` (25k): the planner needs the tag vocabulary (one table);
  `check-plan-shape.py` enforces the rest.
- `pipeline.md`'s **Stage marks** 5.6k, **Handoff output** 4k, **Change name resolution** 4k,
  **Progress visibility** 2k are procedural and script-shaped; candidates for the second change
  once the first is measured.

What carries the pipeline's quality and is not a candidate: `engineering-principles.md`, the
reviewer prompts, the brainstorming checklist, TDD, and the `scripts/check-*.sh` guards. Every
cut above is mechanics that a script already enforces or could.

Decision: two changes — deletion-only first, then mechanics-to-code with fresh before-figures
taken at the tip of the first. Measurement each time follows contracts to the leaf, not phase
files only.

## 3. Dispatch fan-out — what a subagent inherits and never needs

Of the ~32k bytes every subagent inherits:

- The global managed block is rendered by `setup.sh` from a `core` marker in each `.mdc`.
  `rules/flow-manual-review.mdc` has no marker, so its whole body (4.3k, 30% of the block) is
  injected into every subagent for a trigger three lines long. Adding the marker around the
  trigger and the "load `pipeline.md` first" sentence is the entire fix; `setup.sh` is untouched.
- Project `CLAUDE.md`: 6.4k of 10.4k is the skill index plus the **/flow commands summary**,
  read only by the session, never by a subagent. The summary goes with thread 2's copy cut;
  **Lint Fix Priority** and **Never stop the dev workspace's stats service** stay.
- `agent-baseline.md`'s rule table restates the injected block. Decision: **keep it** — it is
  the one place a subagent told to read rules finds them on one screen; 3.5k is cheap insurance.
  The `PreToolUse` hook checks only two markers (`agent-baseline.md`, `verbatim`); the pointer
  sentence is unchanged either way.
- Guards `check-installed-rules.sh`, `check-installed-citations.py`, `check-references.sh` pin
  what the block and the baseline must contain; the cuts keep them green.

Flow-owned, deletion-only:

- `principles-reviewer-prompt.md:176` cite of `project-configuration.md` — drop; the parent
  resolves `[STANDARDS_PATHS]` before dispatch and passes them in.
- Implementer `REQUIRED READING: engineering-principles.md` — point at the bundle's own section
  instead of a second file read.
- Dispatcher-only prose (15-minute ceiling, no-forking, re-dispatch procedure) stays in
  `review-panel.md` and leaves each slot's brief.

Expected per dispatch after both: ~32k → ~17k bytes; ~4k tokens saved per slot, ~20k per five-slot
round, more across N per-task reviewers and implementers. All deletion-only, so it folds into the
first change.

## Step-by-step breakdown

### Change 1 — deletion-only context cut

**What:** Remove stale, restated and rationale text from run-loaded files, split `brainstorm.md`
into a parent file and a planner file, drop the subagent-driven-development invocation, add the
`core` marker to `flow-manual-review.mdc`, trim the project `CLAUDE.md` flow index, drop the
principles-slot `project-configuration.md` cite and the implementer's second principles read, and
move dispatcher-only prose out of slot briefs. Re-measure to the leaf.
**Why:** No behaviour changes, so it lands in a day and gives the true before-figures for change 2;
the repo's cut-never-paraphrase rule makes every deletion visible in the diff.
**Uses:** `skills/flow/SKILL.md`, `skills/flow/brainstorm.md`, `skills/flow/implement.md`,
`skills/flow/review-panel.md`, `skills/flow/principles-reviewer-prompt.md`, `skills/flow-contracts/*.md`
and their `-rationale.md` siblings, `rules/flow-manual-review.mdc`, `CLAUDE.md`, `setup.sh`
(marker rendering, unchanged), `scripts/check-references.sh`, `scripts/check-installed-rules.sh`,
`scripts/check-installed-citations.py`, `scripts/check-contract-budget.sh`.

### Change 2 — mechanics-to-code

**What:** A `flow project get <section>` subcommand (or `scripts/project-get.sh`) returning a
resolved `.flow/project.md` value so no phase file or slot loads `project-configuration.md` at run
time; `workspace-isolation.md` loaded only on `prepare-workspace.sh` failure; the planner handed
the provenance tag table instead of `plan-provenance.md`; then, if measurement still warrants it,
`pipeline.md`'s stage-mark, handoff and name-resolution mechanics into `flow`.
**Why:** These contracts are resolution rules already enforced by scripts; the prose is loaded
several times per run purely to look up one key. Sequenced second because it changes runtime
behaviour and needs tests, and its before-figures should be change 1's after-figures.
**Uses:** `stats/` (`flow` CLI), `scripts/lib/`, `scripts/gather-dispatch-context.sh`,
`scripts/prepare-workspace.sh`, `scripts/check-plan-shape.py`, `skills/flow-contracts/project-configuration.md`,
`skills/flow-contracts/workspace-isolation.md`, `skills/flow-contracts/plan-provenance.md`,
`skills/flow-contracts/pipeline.md`.

### Measurement method

**What:** Sum `wc -c` over every file a run actually reads — router, phase files, each contract a
phase file loads at its point of use, each superpowers skill invoked, the always-on files, and per
role the dispatch bundle plus role prompts — ÷ 4 for tokens; record before/after per load set.
**Why:** kan-372's phase-file-only count under-reported by ~2× and hid where the bytes went.
**Uses:** `wc -c`, `grep -o 'skills/flow-contracts/[a-z0-9-]*\.md'` over `skills/flow/*.md`,
`~/.claude/plugins/**/superpowers/skills/*/SKILL.md`.

### Per-dispatch fixed overhead

**What:** The ~32k bytes every subagent receives regardless of role: harness-injected global and
project `CLAUDE.md`, `MEMORY.md`, and the mandated `agent-baseline.md` read.
**Why:** It is paid per slot in a separate prompt cache, so it scales with panel size and task
count; only file content is a lever — injection is unconditional.
**Uses:** `~/.claude/CLAUDE.md` managed block, `CLAUDE.md`, `rules/agent-baseline.md`,
`~/.claude/hooks/enforce-agent-baseline.py`.
