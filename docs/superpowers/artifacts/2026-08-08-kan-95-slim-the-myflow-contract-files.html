KAN-95 / Highest / myflow-platform / proposal

Slim the myflow contract files

Every /myflow-* command reads its contracts in full before it acts, and that text is resent on every tool call for the whole run. This cuts what a run carries — and removes two things the pipeline was paying for and not using.

The five parts

01as filed

Slim the four loaded contracts

Evict inline rationale into appendices a run never loads, creating two that do not exist yet. Move the state block templates to handoff-blocks.md, whose only consumer is /myflow-status. Re-anchor the budget guard to what lands, plus 25%.

02enables 01

Remove /myflow-info

Its skill and both command files are deleted, and the state diagram and stage tables are rewritten for humans into the root README.md. Nothing loads them — which is why no replacement contract file is created. This is what makes deleting 13,769 bytes from pipeline.md correct rather than a relocation.

03

Slim /myflow-status

Six columns instead of seven — the worktree column restated the change name and wrapped every row. The command reads the state file plus local git and never the network. Merge status stays, because it is local and it is what decides whether the next /myflow-finish integrates or archives.

04follows 03

Delete state self-heal

/myflow-status was the only command that performed it, and part 3 removes the artifact evidence it needed. Rather than leave a contract nothing performs, the mechanism is deleted and the myflow-state-integrity capability retired.

05edits 01's file

Compress the handoff blocks

Related fields fold onto one line, in handoff-blocks.md and in each producing command's copy at once, so the two renderings never diverge. No field is dropped. The fold groups on-disk values onto one line and leaves run-only fields on their own — which is what lets /myflow-status keep omitting exactly what it omits today.

The rule this change had to widen

myflow-contract-economy already carries Requirement: The split is a verbatim partition, with citation repointing as its only edit:

Every sentence of the original file SHALL land in exactly one of the two resulting files, byte-for-byte unchanged. No passage SHALL be summarised, reworded, merged, or authored afresh.

Evicting a mixed passage — one carrying both a rule and the argument for it — authors a new sentence, which that requirement forbids. Found while writing the delta specs, not after implementing against a plan that contradicted them.

The carve-out

The original moves to the appendix byte-for-byte unchanged, so every sentence of the original file still lands in exactly one file, unmodified — the existing SHALL stays true as written. The core gains a new sentence stating the rule, and the ledger quotes that sentence beside the passage it replaces, so the panel checks the two against each other rather than taking the extraction on trust.

Rejected: replacing byte-identity with the ledger corpus-wide. That trades a mechanical property for a reviewed one across every future split, including splits that need no such licence.

How loss is verified

Every task that moves, evicts or extracts prose emits a ledger before its diff reaches the review panel — one row per removed passage:

Removed passageSource headingDestinationPointer left
The path is taken with substr…Resolving a change's worktreespipeline-rationale.md § sameone sentence, cited

The panel checks the table against the diff in both directions: every deletion has a row, every row's destination exists. A missing row and a dangling destination are each a finding.

Why an artifact, and not a reviewer's attention

check-references.sh resolves a citation whenever a heading of that name exists — so a stub carrying a heading and a pointer resolves identically to a stub carrying a heading and nothing. That is KAN-84, and it stays open. The guard cannot see this change's own failure mode, and the proposal says so rather than implying otherwise.

A mechanical no-loss script was rejected: exact for a pure move, broken by the rewording the carve-out requires, with a similarity threshold nobody can tune honestly.

What this costs

Accepted knowingly

A stale state file is now never corrected, and never flagged. Nothing validates a state file against artifacts once self-heal is gone. Moving the mechanism to /myflow-finish was offered and declined.

/myflow-status can no longer say whether a pull request is open. That answer needs the network call part 3 removes, and reporting a state the command did not observe is worse than reporting none.

Parts 2, 3 and 4 are behaviour changes, named as such rather than folded into the slimming claim. KAN-82 and KAN-87 could each claim "not a behaviour change" for their whole diff; this one cannot.
