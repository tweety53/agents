Cut per-command load further

KAN-82 halved what a /myflow-start run loads. Two levers remain, both pure file moves — and the first one turns out not to be the clean cut it looked like.

after this change62,493 core  +  25,760 moved out

The middle band is the whole design. It is 7,252 bytes that look finish-only and are not.

The cut is not clean, and that decides the design

what the measurement found

37% of pipeline.md serves /myflow-finish alone, so moving it out is the same lever that cut jira-integration.md by 70%. But searching for citations into those sections found two that a different command genuinely needs:

PassagebytesCited byReal dependency?
the preserve-session-records.sh outcome table 1,951 myflow-do/SKILL.md Yes — canonical for the prUrl commit path
Temporary artifacts registry 5,301 project-configuration.md, workspace-isolation.md Yes — /myflow-do loads both
Finish contract citations — myflow-start, myflow-status No — they point at reasoning
Why this matters more than the bytes

Moving the whole block and repointing those citations would leave /myflow-do reading workspace-isolation.md and meeting a citation to a file it never loads. That is KAN-82's panel finding F1 — a core term left undefined because its definition moved somewhere no run reads — reintroduced deliberately rather than by accident.

So the two passages are hoisted into the core first, and only what genuinely remains finish-only moves. It costs 7,252 bytes: the core lands at 62,493, not the 55,000 the issue estimated. That number is stated rather than the flattering one.

The files nobody had measured

the second lever

KAN-82 optimised the contracts and never touched the files that load them. skills/myflow-do/SKILL.md is 40,529 bytes — larger than every contract except pipeline.md and project-configuration.md — and is read in full on every run. It carries the same rule-plus-justification prose, so it takes the same treatment.

skills/myflow-contracts/ ├─ pipeline.md 62,493 every command ├─ pipeline-rationale.md editors only └─ finish-contract.md 25,760 /myflow-finish only skills/myflow-do/ SKILL.md 40,529 + SKILL-rationale.md skills/myflow-start/ SKILL.md 28,944 + SKILL-rationale.md skills/myflow-finish/ SKILL.md 28,086 + SKILL-rationale.md not split: myflow-status (17,482 — read-only) myflow-info (4,229 — too small)

The verification a guard cannot do

the lesson KAN-82 paid for

scripts/check-references.sh resolves a citation whenever a heading of that name exists — and the heading-mirroring rule guarantees one exists in both files. So it stays green whether or not a citation still reaches its substance. Three of KAN-82's findings lived in that gap, and all three were found by agents reading rather than by tooling.

Finish contract is cited from four skill files. The plan names each one and requires it to be checked by reading, and forbids offering a green guard as evidence. That requirement is written into the delta spec, not just the plan.

Delta specs

two capabilities modified, one requirement added

RequirementChange

A /myflow-* run never loads a rationale appendix MODIFIED — covers a skill's appendix as well as a contract's

Decisions

five, each with what it ruled out

The finish block's shared passages are hoisted before the move

hoist-before-cut · active
Chosen
Promote the outcome table to its own core section; leave Temporary artifacts registry in the core. Then move what genuinely remains.
Considered
Moving the whole block and repointing — rejected as KAN-82's F1 reintroduced by design. Moving only Finish contract and leaving the registry — rejected as leaving the myflow-do dependency unresolved, which is the harder half.

A skill's rationale lives beside its SKILL.md

skill-rationale-sibling · active
Chosen
skills/<skill>/SKILL-rationale.md. The harness loads SKILL.md alone, and myflow-do/ already holds five .md files.
Considered
Filing them under skills/myflow-contracts/ — rejected because a skill's reasoning is not a contract, and it would make that directory a catch-all its index and budget guard must then police. One shared file for all skills — rejected for the reason KAN-82 rejected one shared contract appendix.

Only the three pipeline skills are split

three-pipeline-skills-only · active
Chosen
myflow-do, myflow-start, myflow-finish — 97,559 bytes, loaded on every pipeline run.
Considered
Adding myflow-status (17,482) — rejected as accruing the saving to the read-only command that matters least. All five — rejected because myflow-info is 4,229 bytes and its appendix would hold almost nothing.

The economy capability widens rather than gaining a twin

widen-economy-capability · active
Chosen
MODIFIED deltas generalising the existing requirements to any file the pipeline loads per run.
Considered
Separate ADDED requirements for skill files — rejected as two near-identical rule sets to keep in step, the duplication this corpus repeatedly punishes. A new capability — rejected because today the rules are identical.

/myflow-info keeps the stage table and loses the contract detail

myflow-info-core-only · active
Chosen
The diagram, the level-1 stage table and every level-2 expansion stay in the core, so it still describes both finish runs and every stage. It gains one pointer line.
Considered
Having it load finish-contract.md too — rejected as making the one read-only command pay the full load, undercutting the split for the command that benefits least.

Open questions

what this plan knowingly leaves unanswered

None. Every question raised across three rounds was answered before the design gate.

The plan

nine tasks in six groups, ordered so each is verifiable when it lands

1.1 / 1.2Hoist what /myflow-do depends on

Promote the outcome table into its own core section and repoint its two callers; confirm the registry stays and record why. Everything later depends on the core being complete first.

2.1Move the finish-only half out

A single line-range extraction into finish-contract.md, plus a pointer stub. Its hardest step is not the move: it is checking all four Finish contract citations by reading, one at a time, with a green guard explicitly not accepted as evidence.

3.1 – 3.3Split the three pipeline skills

Same partition, with worked examples drawn from each file. Frontmatter is never touched — the harness resolves the skill through it. myflow-start's split carries an extra check, since pipeline.md cites its Convergence section.

4.1Index, rule layer, entry points

And a grep proving only /myflow-finish is told to load the finish contract — a hit elsewhere would mean the F1 defect returned by another route.

5.1Widen the guard, regenerate budgets last

The table must key on repo-relative paths, because every skill has a SKILL.md and a bare basename would collide. Budgets are regenerated as the final action of the whole change — KAN-82's table drifted three times by being recomputed too early.

6.1Whole-repository verification

Every guard and harness, a sandboxed installer pass, the measured saving, and a final pass confirming every removed line is one of the two permitted edits.
