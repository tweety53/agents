Why

The proposal's own framing, in two paragraphs.

KAN-17 carried eighteen asks. Slice A took the eleven that change how the pipeline behaves, plus one raised during its planning run. This is the remainder: the asks that change what the operator sees and how the pipeline is configured, plus one appended to KAN-26 after filing.

Two of the eight surfaces they touch have no capability in openspec/specs/ today — the progress view and the manual test guide's shape. That is the same gap slice A found, where the In Review defect survived four archived changes precisely because no requirement existed for it to violate. Both get a spec here rather than a convention.

Decisions

Sixteen, each a choice put to the operator during brainstorming. IDs are immutable — a later round supersedes an entry by ID and never rewrites it.

status-regenerates-handoff

The status report regenerates the handoff rather than replaying a stored one

ChosenOne definition in pipeline.md, two renderers.

RejectedStoring the emitted text — it reproduces the original exactly, then goes wrong silently the moment a worktree is removed or an artifact republished, which is precisely when the operator re-reads it.

progress-uses-harness-widget

The progress view is the harness's widget, not a lookalike

ChosenEvery pipeline command registers its steps with the harness's task mechanism, stated harness-neutrally.

RejectedA printed block in that format — it would sit in scrollback while the live view stayed empty.

no-third-task-marker

tasks.md gains no third checkbox marker

ChosenThe in-progress count comes from the widget alone.

RejectedA - [~] marker — a crashed run leaves a permanently in-progress task behind, in a file two guards parse.

guide-capability-checklist

The guide becomes a capability checklist and keeps its preamble

ChosenOne line per behaviour, grouped by capability; preamble and ## Known incomplete retained.

RejectedChecklist with no preamble — this repository's guides are script invocations, and with no ## apps section there is nowhere else for the commands to live.

rename-reaches-capability

The effort rename reaches the capability, not just the levels

ChosenCapability, levels and state-file key renamed together.

Cost acceptedAn OpenSpec capability rename carries every requirement twice in the delta — ADDED under the new name, REMOVED under the old.

panel-fix-default-unchanged

The panel-fix model keeps the strongest-model default

Chosen"Panel fixes" names the agent that applies a fix — an implementer — so its default stays Opus. The field makes it overridable, not lower.

RejectedTaking KAN-17's wording literally, which would contradict two live requirements at once.

three-separate-model-prompts

The three model choices are three separate prompts

ChosenOne question per role, each naming its default.

RejectedA single defaults-or-customise question, and silent defaults — the latter leaves the field discoverable only by reading the state file.

tab-commands-printed

The tab commands are printed, because they cannot be invoked

ChosenPrinted at the start of each run, with the contract recording why.

Established, not assumedThe SlashCommand tool exposes only type: "prompt" commands; both of these are local. No writable /dev/tty is available either, so the escape-sequence route is closed too.

diagram-table-in-pipeline

The diagram stays small, and a stage table carries the detail

ChosenThree layouts compared visually; the small diagram plus a table won.

Why herepipeline.md is what /myflow-info reads at invocation time, so a diagram held only in the README is one it can never show.

stage-table-two-levels

The stage table has two levels, with eight expansions

ChosenEvery stage that hides substructure gets one — brainstorm, writing-plans, per-task TDD, the review panel, the preflight verdict, the unfinished-work gate, the landing routes, run 2 cleanup.

WhyA single level hid the pipeline's largest machine behind the cell "review panel → 0 findings".

structure-stated-thresholds-cited

Level 2 states structure and cites tuned thresholds

ChosenWhich slots are required, the zero-findings bar, that escalation widens breadth not model — stated. Changed-line counts and trigger lists — cited.

RejectedReproducing the roster table, which is the second copy the README decision rejects one level up.

readme-links-not-copies

The README links rather than copies

ChosenThe README carries neither the diagram nor the table.

Trade-off acceptedA reader browsing on a forge loses the at-a-glance shape.

nine-capabilities-one-change

Nine capabilities, one change

RejectedSplitting again — KAN-26 is already the deferred half of KAN-17, and a third planning run buys smaller review panels at the cost of another issue to track.

join-search-two-todo-statuses

The join search enumerates exactly two To Do statuses

ChosenTo Do and TO DO URGENT, by name.

RejectedDeriving the set from Jira's statusCategory — the same inference slice A forbids for transitions, since TO DO URGENT shares indeterminate with In Progress. Including it here does not reopen that rule: a search filter performs no transition.

join-retitles-generic

A joined issue is retitled generically

ChosenThe title becomes myflow follow-up; items append under a dated ## From <KEY> heading; labels are unioned.

RejectedListing every source in the title, which grows without bound.

vocabulary-json-key-only

The vocabulary guard gains the JSON key form and nothing else

Chosen"effort": is added. medium and high are not.

WhyThey are ordinary English here, Medium is a Jira priority, and the only way to silence the false hits is a marker on a line telling the truth — which the guard's own header says teaches it to lie.

Boundaries

Non-goals

  • The three states, the panel roster, plan provenance, the staging and commit split, and the finish verdict scripts — all untouched.
  • No new guard script.
  • No amendment to myflow-planning-gate, which slice A wrote in the preceding change.
  • No migration pass over existing state files.
  • No hook written into settings.json.

Risks accepted

  • The progress widget is harness-specific; on Cursor and Codex the printed fallback is the only path exercised until someone tests there.
  • The capability rename produces a bulky delta — every requirement written twice.
  • A creating run now asks four questions before brainstorming. A revision round asks none.
  • The guide's register is prose; only the panel's principles slot checks it.
  • A later editor could blur the structure-here / thresholds-cited line. No guard can catch that.
