No uncommitted-diff helper for subagent-driven-development review packages under NO-COMMITS

kan-53-myflow-no-uncommitted-diff-helper-for-subagent Jira KAN-53 → In Progress Planning effort default Impl Sonnet Panel Sonnet Fixes Sonnet

01 Why

/myflow-do's NO-COMMITS rule forbids committing until a PR exists, so skills/myflow-do/SKILL.md tracks per-task and per-fix-round review bases as git rev-parse HEAD. Since HEAD never advances while nothing is committed, every task records the same base — git diff TASK_BASE for task 2 silently includes task 1's still-uncommitted work too. It is not the isolated diff the review loop needs.

This was worked around by hand during KAN-31's /myflow-do run using git stash create to get a non-destructive snapshot object. This change makes that reusable rather than re-derived per run.

02 What changes

  • Add skills/myflow-do/scripts/checkpoint — prints a non-destructive snapshot of the current index+worktree state, suitable as an isolating BASE.
  • Add skills/myflow-do/scripts/uncommitted-review-package PLAN_FILE BASE [OUTFILE] — writes a review package (stat + diff) into the same .superpowers/sdd/<plan>/ workspace review-package already uses, minus a Commits section.
  • Rewrite SKILL.md step 4 and the fix-round paragraph in step 5 to call these scripts instead of the inline git rev-parse HEAD prose.
  • Add scripts/test-uncommitted-review-package.sh covering both scripts.

03 Design

Context, goals, and how the two scripts fit together.

Goals

  • Isolate exactly one task's (or fix round's) own uncommitted changes from prior tasks' still-uncommitted changes, without committing anything.
  • Match review-package's existing package shape so reviewers read one file, exactly as they already do for the committed case.

Non-goals

  • Editing subagent-driven-development's review-package script — it ships from the superpowers plugin cache, not this repository.
  • Any change to the whole-branch final-review.diff, which is intentionally cumulative and has no isolation bug.

Data flow

per task
TASK_BASE=$(skills/myflow-do/scripts/checkpoint)
# ...implementer subagent works, leaves changes uncommitted...
skills/myflow-do/scripts/uncommitted-review-package tasks.md "$TASK_BASE"
# ...task reviewer reads the single package file printed on stdout...

Fix rounds follow the identical shape with FIX_BASE / fix-round-N.diff as the explicit OUTFILE, so a re-review gets a distinct, freshly named file.

04 Decisions

Isolate per-task/per-round diffs via git stash create, not a real commit

id
stash-create-isolation
status
active
chosen
Record BASE = git stash create (falling back to HEAD on a clean tree) before each dispatch — a non-destructive snapshot that actually isolates each task's own changes.
considered
Keeping git rev-parse HEAD and asking reviewers to manually exclude prior work — re-creates the hand-built process this change eliminates. Committing per task and squashing later — violates NO-COMMITS directly.

Two small single-purpose scripts, not one combined script

id
two-scripts-not-one
status
active
chosen
A checkpoint script and a separate uncommitted-review-package script, matching how subagent-driven-development already splits sdd-workspace / review-package / task-brief, keeping BASE an explicit variable the parent tracks.
considered
One combined script remembering its own last checkpoint internally — makes BASE implicit state, diverging from how step 4 already documents the loop.

05 Risks & trade-offs

a git stash create object is unreachable from any ref and can be garbage-collected
it only needs to survive from one checkpoint call to the next uncommitted-review-package call in the same session — the same lifetime review-package's own BASE/HEAD arguments already assume.
git stash create on a clean tree prints nothing, which a naive caller could mistake for an error
checkpoint detects this and prints the current HEAD sha instead, exercised directly by the test suite.
the single-ref diff also picks up changes made by anything other than the dispatched subagent
this is the same trust boundary git diff TASK_BASE already had; nothing here widens it.

Migration plan

None needed — additive only: two new scripts and a rewrite of two paragraphs in SKILL.md. No state file, ledger, or review-package format changes shape. Rollback is reverting the commit.

Open questions

None.

06 Spec — myflow-uncommitted-review-package

New capability, added in full (no existing requirements modified).

A checkpoint isolates uncommitted work without touching any ref

checkpoint SHALL print git stash create's output when the worktree carries uncommitted changes, or the current HEAD sha when clean — and SHALL NOT modify HEAD, the index, or the stash list either way.

Scenario · dirty tree yields a stash-create snapshot
  • when checkpoint runs against a worktree with uncommitted changes
  • then it prints a valid commit-ish distinct from HEAD, and git status/git stash list/HEAD are unchanged
Scenario · clean tree falls back to HEAD
  • when the worktree has no uncommitted changes
  • then it prints the current HEAD sha

A review package diffs BASE against the live working tree

uncommitted-review-package PLAN_FILE BASE [OUTFILE] SHALL write a files-changed stat and a -U10 diff of BASE against the working tree — never HEAD — into the same plan-scoped .superpowers/sdd/<plan>/ workspace, with no Commits section.

Scenario · a later task's changes are isolated from an earlier task's
  • when task 1 changes, a checkpoint is recorded, then task 2 changes further
  • then the package contains only task 2's changes
Scenario · the output file has no Commits section
  • then the file has ## Files changed and ## Diff, and no ## Commits
Scenario · a re-review after a fix round gets a distinct file
  • when invoked again with a different BASE and an explicit OUTFILE
  • then the new package is written there, leaving the prior file intact

Invalid arguments fail the same way review-package's do

Scenario · missing plan file
  • then exits non-zero, reports no such plan file: <path>, writes nothing
Scenario · unresolvable BASE
  • then exits non-zero, reports bad BASE: <base>, writes nothing
