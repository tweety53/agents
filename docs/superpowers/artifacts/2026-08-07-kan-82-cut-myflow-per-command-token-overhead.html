Cut myflow per-command token overhead

Every /myflow-* command reads its contract files before it does any work. Two of those files have grown big enough that the read dominates the run. Split each into the rules a command obeys and the reasoning an editor needs — and ratchet the result so it cannot grow back.

what a /myflow-start run loads today bytes
skills/myflow-contracts/pipeline.md103,326
skills/myflow-contracts/jira-integration.md52,783
skills/myflow-contracts/state-file.md15,951
stays in the core certain to move — a whole section, one command needs it prose: an unknown share of it is rationale

Bars are to scale against each other. Measured at adedf66 with wc -c skills/myflow-contracts/*.md. The hatched band is prose, which is an upper bound on what can move, not a forecast — plenty of prose states rules and stays.

Why

the problem

The content isn't the problem. The audience mix is. Each contract file interleaves rules an agent must obey mid-run with the reasoning behind those rules, which serves whoever edits the contract. The agent pays for both on every run; the editor needs both once, rarely.

pipeline.md is read by every command. jira-integration.md is read by three of them. A /myflow-start run pays both, plus state-file.md, before it asks its first question.

The constraint that shapes everything

A split must not produce two independently authored statements of one rule. That is what makes this a partition rather than a rewrite: every sentence lands in exactly one file, byte for byte. Nothing is authored, so nothing can drift.

What changes

five files where there were two

One test decides where every passage goes, applied to paragraphs and tables, never to clauses:

A passage is core if removing it would change what an agent does.
A passage is rationale if removing it changes no agent behaviour.

So tables, ordered steps, handoff templates, runnable code and every prohibition stay in the core. Justifications of an ordering, rejected alternatives, history, measurements and commentary about the document itself go to the appendix. The test is behavioural, not typographic — pipeline.md's "Never substitute a commit count" is a prose paragraph and it is core.

skills/myflow-contracts/ ├─ pipeline.md core → every command ├─ pipeline-rationale.md appendix → editors only ├─ jira-integration.md core → start, do, finish ├─ jira-integration-rationale.md appendix → editors only └─ jira-followups.md whole → finish run 1 only

jira-followups.md keeps its rules and its reasoning together, because only one command loads it. Moving it out at all is the largest single lever here and needs no partition judgment: it is a contiguous 457-line block, 67% of its file, that /myflow-start and /myflow-do stop paying for entirely.

Appendices mirror their core's heading tree

Same ## headings, same order. A citation then resolves against whichever file its path names, and an editor reads the two side by side. A section that is wholly normative leaves its appendix heading present with no body — missing rather than dropped, so it is visible that the section was examined rather than skipped.

A byte budget, so the cores cannot grow back

New scripts/check-contract-budget.sh, carrying a path-to-max-bytes table covering every skills/myflow-contracts/*.md. A file in that directory with no budget row is itself a failure, so a contract added later cannot slip past the ratchet.

Each budget is the size the split actually achieves, plus 25% — never a target declared up front. A target-first budget would create pressure to push normative text into an appendix to make a number, which is the one way this change could do harm rather than merely disappoint.

And a rule nothing enforces

A /myflow-* run never loads an appendix. Stated in SKILL.md, in each core's header and in the always-on rule; deliberately unguarded, the same treatment this corpus gives its other judgment rules.

What is out of scope

named, not silently dropped

The issue's third cut — pruning the harness system prompt — is an operator action against an installed environment (uninstalling unused plugins), not a change to this repository. It is worth doing and belongs on its own issue.

project-configuration.md (45,236 bytes), workspace-isolation.md and plan-provenance.md are not split. They are ratcheted where they stand by the new guard, and a later split of any of them is a budget edit plus the same partition work.

And no rule changes. Nothing is added, removed or reworded. Every /myflow-* command behaves identically before and after.

Modified — myflow-contract-distribution

Its requirement enumerates the contracts directory as holding exactly six files. That is already wrong on this tree — build-green.md, plan-provenance.md and workspace-isolation.md all exist and none is listed. The enumeration is replaced by a two-directional agreement rule: every file present is named in the index, and every file the index names is present. An enumeration that went stale through three changes is not repaired by a fourth enumeration.

Its installer requirement gains the scenario that files added to the directory ship to all three harnesses with no installer edit — verified against the source: install_skills (setup.sh:188) symlinks whole skill directories.

Decisions

nine, each with what it ruled out

Scope is the two contract splits; the system-prompt cut is not in it

scope-contract-splits-only · active
Chosen
Split pipeline.md and jira-integration.md only — pruning the harness system prompt is an operator action against an installed environment and needs its own issue.
Considered
All three cuts with an in-repo stand-in for the third — the real lever is uninstalling plugins, which no repo change reaches. pipeline.md alone — the follow-ups move is a pure move with a large payoff and no new mechanics. Every contract file at once — a much larger partition surface for files two commands load rather than five.

The rationale goes to a sibling appendix, one per contract

sibling-appendix-per-contract · active
Chosen
<name>-rationale.md beside each core, cited by section name so check-references.sh verifies the link.
Considered
One shared rationale.md — an editor of one contract would load the reasoning of all of them, the same audience mismatch one level up. A runtime-stop marker inside one file — a Read still pulls the whole thing, so it saves nothing that matters. Deleting the rationale — several sections of this corpus exist precisely because an editor re-derived a decision wrongly, and git history is not where an editor looks.

The core is a strict partition of today's text, not a rewrite

strict-verbatim-partition · active
Chosen
Every sentence lands in exactly one file, verbatim; the only permitted edit is repointing a citation whose target moved.
Considered
Partition then tighten the core for flow — the diff stops being a pure move and every reworded line becomes something the panel must check by hand. Rewrite the core as a fresh summary — exactly the two-statements-of-one-rule failure the issue forbids.

jira-integration.md splits on both axes, into three files

jira-three-file-split · active
Chosen
Core, rationale appendix, and jira-followups.md carrying its rules and reasoning inline.
Considered
Core/appendix only — Follow-up issues' normative half would stay in the core and /myflow-start would keep paying for it. By-command only — leaves the largest remaining file unpartitioned. A fourth jira-followups-rationale.md — the only command that would benefit is the only command that loads the file at all, and it would separate this corpus's most adversarial reasoning from the rules it justifies.

The appendix mirrors the core's heading tree

appendix-mirrors-headings · active
Chosen
Same headings, same order; a wholly normative section leaves an empty appendix heading.
Considered
Free-form headings grouped by topic — a citation must then name the right heading and the two structures drift. One flat list keyed by core heading — long headings with no nesting, in files that nest three deep today.

Budgets are measured in bytes and declared inside the guard

budget-bytes-in-guard · active
Chosen
A path-to-max-bytes table inside the script. Deterministic, no tokenizer dependency, and raising a budget is a visible diff in the guard.
Considered
Lines — a long-line file cheats it. A budget in each file's own header — the file can then raise its own limit. A budget in .myflow/project.md — that file configures a consuming project, and this is a rule about this repository's own sources.

Each budget is the achieved size plus 25%

budget-achieved-plus-25 · active
Chosen
Split first, then set each budget from the resulting byte count plus 25%. The guard can never fail the split itself.
Considered
A target declared up front — creates pressure to push normative text into an appendix to make a number. Achieved size with no headroom — forces a guard edit for every ordinary sentence added.

The no-appendix-at-runtime rule is stated, not enforced

runtime-rule-unenforced · active
Chosen
State it in three places; enforce nothing.
Considered
A guard failing when a skill names a -rationale.md in a load instruction — machinery around a rule no observed failure has broken, in a repository that already carries eight guards.

The budget guard covers every contract file, not only the split ones

budget-covers-all-contracts · active
Chosen
Every file in the directory gets a budget, and a file with no entry is itself a failure.
Considered
Only the files this change splits — project-configuration.md at 45,236 bytes is the next file to have this problem and would grow unwatched. Also budgeting every SKILL.md in the repository — widens this change's surface; those are ratchetable later by adding rows.

The plan

six tasks, ordered so each is verifiable when it lands

1.1Move the follow-up contract into its own file

A pure move of a contiguous 457-line block, plus the citations pointing into it. No partition judgment needed, and it proves the citation-repointing loop before anything harder.

Verified by: a line-multiset diff against HEAD showing no line disappeared, check-references.sh green, and a mutation test proving the guard actually looked.

2.1Partition jira-integration.md

The smaller partition first, so the mechanics and the line-multiset check are proved on it. The task carries six worked examples from the real file so the core/rationale boundary is not left to taste.

Verified by: line-multiset diff, an empty heading-sequence diff between core and appendix, and the mutation test.

3.1Partition pipeline.md

The same operation on a file three times the size, cited by 132 backticked references across the corpus — and one that cites itself throughout, so a self-citation whose target moved repoints while one whose target stayed does not.

Also verified: that /myflow-info is still satisfiable — the state diagram and all eight level-2 expansions must be in the core, since that command reads the file live and may not answer from memory.

4.1Update the index, the rule layer and the entry-point files

SKILL.md, rules/myflow-manual-review.mdc, CLAUDE.md and AGENTS.md — and the three files already missing from the index get rows too.

Verified by: an empty diff between the directory listing and the index, and a grep proving no skill names an appendix in a load instruction.

5.1Write the budget guard and its harness

Last, because its numbers are what the four tasks before it produced. The task carries the full guard and the full harness, plus the six budgets computable today from files this change does not touch.

Verified by: the harness's five cases, a real over-budget mutation on the live tree, and a run from /tmp proving the guard is self-scoped rather than silently scanning nothing.

6.1Whole-repository verification

All five lint guards, all twelve test harnesses, a sandboxed setup.sh global proving the new files reach all three harnesses with git diff setup.sh printing nothing — and a final pass confirming every difference from the originals is a moved line or a repointed path.

It also records the actual saving, and reports the real figure rather than a target.

The risk, stated plainly

what could make this a smaller win

The achieved size is not known until the partition runs. The issue targets pipeline.md at roughly 8k tokens down from 34k; the measured 78% prose fraction makes that plausible but is an upper bound, since normative prose stays in the core. If the partition lands the core at 40,000 bytes rather than 24,000, that is the result and the budget records it.

Setting budgets from achieved size rather than from a target is precisely what makes that outcome a smaller win rather than a failed change — and what keeps anyone from moving a rule into an appendix to hit a number.
