Remove the manual test guide and its gate

/myflow-do stops writing docs/manual-test/<name>.md. The handoff prints the commands for running what is in scope instead. The operator still reviews the diff and still runs the apps — what goes away is the file, its checkboxes, and the two guard signals read back from them.

Why

The guide costs a generation step on every run and a refresh on every fix round, and it produces a second completion record beside tasks.md that check-unfinished-work.sh must then police — two of its four signals exist only to read a file the pipeline itself wrote.

What an operator actually needs at IN_PROGRESS is the preamble: the commands to run whatever is in scope, with absolute paths and this worktree's resolved URLs. That part survives, printed rather than written down.

What changes

Deleted
  • The myflow-manual-test-guide capability — all three requirements
  • docs/manual-test/ — the directory and its fourteen committed guides
  • Two guard signals — the missing-guide check and the ## Known incomplete scan in check-unfinished-work.sh
  • One planning path — the staging exclusion list drops from three to two
  • The status bullet — the guide's path and box count in /myflow-status
Replaced by
  • A Run it: section in the IN_PROGRESS handoff template
  • /myflow-do section 6, retitled Resolve the run instructions — writes no file
  • One requirement in myflow-handoff-output, absorbing the no-runnable-app case
  • A renamed plan commit — chore(<name>): plan and session records
The gate itself is unchanged. IN_PROGRESS still means the staged diff awaits review and the run. No state is added or removed, and nothing records whether the operator ran anything — as before.

The handoff, after

Worktree:   <absolute worktree path>

Run it:
  <command>          # <app or check name>
  <command>

Review the diff, then run it:
  <the review command that matches the git state on the Staged line>
  open -na "IntelliJ IDEA" --args "<absolute worktree path>"

Every path absolute; every URL the one this worktree resolved from its workspace id, never the project's declared base. A repository with no runnable application — this one — lists its guard and test commands instead.

Decisions

The human gate keeps both halves

gate-keeps-both-halves · active

IN_PROGRESS continues to mean “review the staged diff and run the apps.” Only the generated artifact and its checkboxes disappear.

Diff review only — running the apps catches what a diff cannot; dropping it narrows the pipeline's only behavioural check. No gate at all — a state-machine change, not an artifact removal, leaving nothing before the irreversible step.

Run instructions are printed, not written to a file

run-instructions-in-handoff · active

The handoff carries the commands directly. Nothing on disk, nothing committed, nothing read back.

A file with no checkboxes — keeps the file, the path and the staging exclusion; the removal would be cosmetic. Cite .myflow/project.md and stop — loses per-worktree URL resolution, sending the operator to a port this worktree does not bind.

The template lives in handoff-blocks.md

template-in-handoff-blocks · active

One definition, two renderers: /myflow-do carries the block it prints, /myflow-status regenerates from the same template.

Each command composes its own — cheaper diff, but the two drift; that is the failure the file was split out to prevent.

Both guide signals are deleted from the guard

delete-guide-signals · active

check-unfinished-work.sh keeps two signals: unticked plan boxes (including <name>-fix-N sub-changes) and open panel findings. Exit codes unchanged.

Relocate ## Known incomplete onto tasks.md — rework for a section the plan's own unticked boxes already express.

docs/manual-test/ is deleted outright

delete-guide-directory · active

The directory and its fourteen guides go. Git history retains them.

Keep them as history — leaves a directory nothing produces and nothing reads.

The planning-path list drops to two

two-planning-paths · active

The paths /myflow-do never stages become openspec/ and docs/superpowers/.

Keep the three-path list — an exclusion for a path that cannot exist is a contract stating something untrue.

The capability is removed; one requirement moves

remove-capability-move-requirement · active

The capability is deleted in full. One new requirement lands in myflow-handoff-output, which already owns handoff shape and the absolute-path rule.

Repurpose it in place — keeps a capability name that no longer describes what it governs. Remove it and add nothing — the run instructions would be governed by a skill file alone.

The plan commit is renamed, and the grep matches both wordings

rename-plan-commit · active

gather-self-review-context.sh matches plan(, test guide and| and) session records at both of its sites, so changes already in history keep resolving.

Keep the old subject — names an artifact that no longer exists. New wording only — every older change stops resolving its plan commit, and IMPL_SHA then picks that commit up as the implementation commit. A wrong answer, not a missing one.

Plan

  1. Drop the guide signals from the unfinished-work guard
    Harness first: delete every guide fixture, add a case proving an absent directory is not a signal, watch it fail, then strip the guard. count_unticked and unreadable stay — the plan signal uses both.
  2. Match both plan-commit wordings in the self-review context script
    A new-subject fixture beside the two existing old-subject ones, then one ERE alternation at each of the two grep sites.
  3. Drop docs/manual-test/ from the staging exclusions
    The harness, then the git chain in all three contract files — which is where the commit subject is renamed too.
  4. Replace /myflow-do section 6 with run-instruction resolution
    Retitled, writing no file, keeping the absolute-path and workspace-URL rules verbatim in substance. Budget ratchet checked in the same task.
  5. Put the run instructions into the handoff template
    The Run it: section is on-disk, not run-only, so /myflow-status regenerates exactly what /myflow-do printed.
  6. Delete the directory and sweep the remaining contract prose
    Ten files, two stale script comments, one fixture path. Preserved records under docs/superpowers/ are historical and are not rewritten.
  7. Update the documentation digests and command files
    Six digest sites plus both myflow-do command files. The copies stay deliberately non-identical — the facts are fixed, the wording is not.
  8. Full verification pass
    Twelve harnesses, six lint guards, a sandboxed installer run, and openspec validate --strict. Every hit fixed by editing the line — never a suppression, never a narrowed guard.
