myflow proposal/KAN-110

Lighter auto code review by default

The review panel runs at one fixed weight for every change. Make the weight a recorded, per-change choice — and make the cheap one the default.

State · STARTED Planning effort · default Models · Sonnet throughout

Why

Every /myflow-do run dispatches the same required panel — Primary, Bugbot and Principles — plus whichever conditional slots the trigger table auto-includes, and runs two reviewers on every single task. Nothing about that roster varies with the change.

So a documentation-only diff pays what a migration touching auth pays, and Bugbot, the most expensive of the three, is mandatory on both. Three things already vary per change and are recorded in its state file: the planning effort and the three model roles. The roster is the obvious fourth, and it is the one that governs most of the cost.

The three rosters

lightdefault
Primary Principles Code review (low)
Conditional slots: one prompt, include-all recommended
standard
Primary Principles Bugbot
Conditional slots: one prompt, include-all recommended
full
Primary Bugbot Principles
Conditional slots: auto-included on trigger — today's behaviour, unchanged

Every preset dispatches exactly three required slots. No preset reduces that number, and full reproduces the panel exactly as it runs today — which makes the whole feature opt-out rather than a rewrite.

What changes

A recorded field

reviewPanelRoster joins planningEffort as a top-level state-file string. /myflow-start asks for it once, on the run that creates the change, as a fourth question beside the effort level and the three model roles. A revision round states the recorded value and does not ask. Every other command carries it forward verbatim.

An absent key reads as light — the same absent-key exception planningEffort and models already carry. No existing state file becomes unparseable, and no migration pass runs.

The light preset's third slot

Slot 1 under light is a general-purpose subagent on the panel model, told to invoke the harness's code-review skill at effort low against the panel diff and return its findings in its report. Its model is known, so the ledger records it rather than unknown (agent-defined). Its findings take ordinary rows and marker lines; the panel record's format is untouched.

Where a harness has no code-review skill, the slot becomes a general-purpose reviewer briefed for high-confidence defects only, and the panel record names the substitution. It is never dropped — a missing harness feature is not a way to run a two-slot panel.

Conditional slots are offered, not assumed

Under light and standard, the trigger table is evaluated unchanged; what changes is what happens next. Every slot whose trigger fired goes into one multi-select prompt naming the slot and the trigger that fired it, with include-all recommended. A slot the operator declines is recorded as declined — distinct from one whose trigger never fired.

Per-task review collapses

Per-task review is where most reviewer dispatches happen, so the preset governs it too. Under light and standard the spec-compliance and code-quality pair becomes one combined reviewer per task. Under full both still run. The ledger records which shape ran.

Bugbot reads for surviving mutants

Wherever Bugbot is dispatched, its brief now includes reasoned mutation testing: for each behaviour the diff changes, mutate it — flip a condition, drop a guard, move a boundary — and establish whether an existing test fails. No framework is added and no score is computed.

A mutation no test catches is a surviving mutant, raised as an ordinary finding. It blocks the handoff until a test is added or the operator withdraws it with a reason. Bugbot appears in standard and full, so the light default gets no mutation reading — consistent with it being the cheap option.

The handoff bar does not move. Zero open findings at any severity, under every preset. A minor finding blocks exactly as a critical one does, and the escalation ladder, fix rounds, record format and operator handback are all unchanged.

A preset sizes how much reading the panel does. It is not a way to skip review — which is why the invariant is written into the delta spec rather than left implied.

Decisions

ChosenAsked once by /myflow-start on the creating run and recorded — matching how the effort level and model roles are already chosen.
ConsideredAsked at /myflow-do each run — a fix round could silently run a different roster than the first pass. A project-level default — cannot tell a documentation change from a migration in the same repository.
Conditional slots under the lighter presetsconditionals-ask-not-auto
ChosenDowngrade the trigger table from auto-include to one multi-select prompt. The trigger still fires and the operator still sees it.
ConsideredLeaving auto-include — the cheap preset would not be reliably cheap. Cutting the conditionals entirely — a migration would get no extra lens, with nothing saying a trigger had fired.

ChosenToday's behaviour exactly. The no-change option, which makes the feature opt-out.
ConsideredEvery slot always, ignoring triggers — heavier than the panel has ever run. Every slot plus the low-effort reviewer — a seventh reading with no stated reason to exist.
Scope of the presetpreset-covers-per-task-review
ChosenIt governs the per-task review as well as the final panel, because that is where most dispatches happen.
ConsideredFinal panel only — simpler, but barely lighter on a change with many tasks.

ChosenThe harness's code-review skill at effort low. Its low levels are defined as fewer, high-confidence findings — exactly what a light panel wants.
ConsideredThe cavecrew-reviewer agent — output is deliberately compressed, and a committed record should read as ordinary prose. A narrowed Superpowers reviewer — the same reviewer slot 0 runs, so the panel would carry two readings from one reviewer.

ChosenSubstitute a general-purpose reviewer and name the substitution in the record.

Open questions

None. Every question raised across five planning rounds was answered.

Risks

A lighter default finds fewer defects. The required count stays at three under every preset, conditional triggers still fire and are surfaced rather than dropped, and the zero-open-findings bar is unchanged. standard and full are one recorded value away.

The code-review skill is harness-provided and may vanish or be renamed — the stated fallback substitutes and names the substitution, so the panel never silently shrinks.

Reasoned mutation testing has no ground truth and can produce false survivors — a survivor is an ordinary finding, so the existing handback and withdrawal-with-reason path resolves a disputed one exactly as it resolves any other.

An extra prompt per run under the lighter presets — it fires only when a trigger actually fired, which the trigger table already keeps rare.
