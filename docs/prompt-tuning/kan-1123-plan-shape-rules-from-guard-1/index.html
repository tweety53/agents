Why picked

1. Defect class: a finding describes a kind of defect and cites some sites as examples; the fixer repairs those sites and writes a check that lists them, so every unnamed instance of the class survives. 2. No current rule covers it: implementer-brief.md's FIX DISPATCH paragraph (quoted as `before`) tells the fixer to "fix exactly what that line names ... at its root cause", which a fixer reads as the cited sites; no paragraph of implementer-brief.md, implement.md, sdd-dispatch.md or engineering-principles.md says a class finding reaches its uncited instances. 3. It generalises: in one run, three consecutive fix rounds by two fixer kinds repeated it on one class (a gated fix renamed only the sampled ids, a panel fix added a denylist of exactly the reviewers' named ids and drew the class back as a new Important, and the next fix kept a denylist for multi-word ids that still passes about twenty such ids); the same shape applies to any finding about a naming rule, an unchecked error pattern, a missing guard clause or an unsafe call repeated across sites, in any language or layer. 4. It is a principle, not a patch: "a class finding is fixed for its class, and its check detects the class by shape, not by a list" names no id, file or tool.
