Why picked

1. Defect class: a test of a choice uses inputs on which the alternative choices give the same result, so the choice is unpinned. 2. No rule covers it: the Testing principles section reads "Tests are written first, assert observable behavior rather than implementation, run fast and deterministically, and fail for exactly one reason." and its violation list names mocks, sleeps, order dependence, weakened assertions, deleted tests and measured geometry bounds, but nothing about choosing inputs that tell alternatives apart. 3. It generalises: this one run produced five mutation survivors of the class across Go and TypeScript in three rounds: F11 (an upsert precedence test with equal areas), F12 (an author-versus-committer date choice tested with equal dates), F17 (a btrim tested with no padded input), F18 (busiest-first tested with a busiest item also first by name) and F20 (model-first grouping tested with one model). The same shape applies to any sort, merge, fallback, COALESCE or precedence code. 4. It is not patch accretion: it states one principle about test input selection, discriminating inputs, rather than a rule about heatmaps or git dates.

### Testing principles

Tests are written first, assert observable behavior rather than implementation, run fast
and deterministically, and fail for exactly one reason.

**Violation looks like:** a test asserting that a mock was called rather than what
changed, a sleep used for synchronisation, a test whose result depends on execution order
or the wall clock, an assertion weakened rather than a bug fixed, a test deleted or
`@Ignore`d in the same diff that changed the behavior it covered, or a geometry assertion
on a measured or reported bound (Compose's semantics bounds, coerced to the parent's) where
the property under test is what is drawn — an overflow is visible only in the rendered
pixels, so the assertion passes on the unfixed code.

### Testing principles

Tests are written first, assert observable behavior rather than implementation, run fast
and deterministically, and fail for exactly one reason.

**Violation looks like:** a test asserting that a mock was called rather than what
changed, a sleep used for synchronisation, a test whose result depends on execution order
or the wall clock, an assertion weakened rather than a bug fixed, a test deleted or
`@Ignore`d in the same diff that changed the behavior it covered, or a geometry assertion
on a measured or reported bound (Compose's semantics bounds, coerced to the parent's) where
the property under test is what is drawn — an overflow is visible only in the rendered
pixels, so the assertion passes on the unfixed code.

**A test of a choice is fed inputs that separate the alternatives.** When a test pins which
rule the code applies (an order, a precedence, a grouping, which of two sources wins), its
inputs make every plausible alternative rule produce a different result. Inputs on which the
alternatives agree leave the choice unpinned and the test green against its mutants: the
busiest item also first by name, a single group where the rule groups, two sources holding
one value.
