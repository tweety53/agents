Defect class

A departure on a new state or new view is attributed to the change without checking whether the element's styling ships unchanged in a component the change did not touch.

Finding

"departures, this change's: block teal highlight border + teal `Text` kicker vs plain card + magenta kicker"

- Severity: Important (visual-verify departure)
- Location: templates-E4 (`verify-report-visual-verify-gymie.md:40`)

none

Fix

none

Why picked

1. Defect class: provenance is judged by view novelty, not per element. 2. The quoted rule makes every departure on a new view the change's own, with no per-element check. 3. It generalises: every menu, sheet or state added to a shipped screen reuses shipped components (rings, kickers, cards); KAN-942 shows the same misattribution class for views without a baseline. 4. It states a principle (attribute per element by provenance), not a special case. Cost: the verifier recorded the E4 teal ring and kicker as this change's; the fix round spent time hunting them, and both were af16eec4's blockMenuRing and the KAN-175 kicker at the merge base.
