Why picked

1. Defect class: a plan's task writes a file, key or record that existing code reads, at a path or in a shape the reader does not read, and the task's own test asserts the writer's choice, so the plan's verified diff runs green while every reader sees nothing. 2. No current rule covers it: the plan-review rubric's Codebase details lens (quoted as `before`) checks statements about existing code and that named paths exist, which a reviewer reads as excusing every path a task newly creates; no lens of plan-review-rubric.md or plan-reviewer-prompt.md asks for a new write to be compared with its existing reader. In this run both plan reviews read the design's named reader and recorded it as checked, and neither compared it with the path the task's code wrote; the code panel's primary slot raised it as round 0's Critical, a later slot, from the same reader. 3. It generalises: every plan that adds a producer for an existing consumer carries the class — a record file a gate and a report read, an environment variable a script reads, a JSON field a client decodes, a stage-file line another subcommand parses, a store key a query selects — in any language or layer; and a plan's self-verification by its own tests cannot catch it, because the test pins the writer, so only a reader comparison at plan review does, before an implementer spends a task and a panel spends a Critical on it. 4. It is a principle, not a patch: "every new write is checked against its existing reader" names no file, path, tool or change, and extends the lens's existing rule from claims about code to writes into it.
