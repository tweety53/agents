Why picked

1. Defect class: a self-measured departure the change itself owns is reported as a leftover rather than fixed. 2. No rule covers it: the measure-before-hand-back rule reads "A leftover of any size — a 1dp offset included — is closed or named with its cause, never reported clean because it is small", and nothing defines a cause, so the implementer's hand-back listed "Stage runs panel shows latest 5 + \"Show all 31\", prototype 6 rows" under Prototype leftovers with no cause, and the parent accepted it. The verifier then classed it as this change's defect, and the run paid a verifier pass, an in-run fix task and a panel round for it. 3. It generalises: the same allowance governs every compose-and-measure step — every plan-time capture task baselined against a mockup or prototype (the planner cites this rule for them), and every visual fix round. The verifier already attributes each leftover to the merge base, the fixture or a frame conflict; the implementer side has no matching bar, so any project with design frames can hand back an own departure as a leftover. 4. It is a principle, not a patch: a cause is something outside the change's control, and a departure the change controls is fixed, whatever the view or property.
