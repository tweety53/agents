Why picked

1. Defect class: a job restarted on a change of some state (a keyed effect, a latest-only collector, a switch-to-latest stream) writes that state before its work completes, so its own write cancels the work in flight and the result never lands. 2. No rule covers it: engineering-principles.md's Robustness section, the one section on failure behaviour, lists swallowed exceptions, missing timeouts and silent fallbacks as violations, nothing on work that cancels itself; no implementer instruction file (implementer-brief.md, implement.md, sdd-dispatch.md, engineering-principles.md) mentions cancellation or restart triggers. 3. It generalises: every Compose LaunchedEffect or produceState with keys, every snapshotFlow/collectLatest, Kotlin flatMapLatest/mapLatest, RxJS switchMap and a React effect whose cleanup aborts its request restart on their trigger; a bookkeeping write (an 'asked', 'loading' or 'inFlight' flag) folded into the trigger cancels each of them the same way, and it passes every test whose fake answers instantly, as here, where only a 300 ms delayed answer exposed it. 4. Not patch accretion: the update states one principle (work keyed on some state never changes that state until it has finished, or runs outside the keyed scope) rather than naming LaunchedEffect or this screen.
