Type

implementer · scope generic

Defect class

A port of existing code into another language, library or process model keeps the original's happy path but loses a failure behaviour the original had, because the port's tests were copied from the original's harness, which never exercised that failure.

Finding

**Severity:** Important
**Slot:** gated per-task reviewer (task 4)
**Location:** stats/internal/guard/livestorecopy.go:811

`stats/internal/guard/livestorecopy.go:811-828` (`copyStore`) — when `psql` exits before `pg_dump` has written everything (its `ON_ERROR_STOP=1` on the first failing statement, a refused connection, any early exit), `live-store-copy up` hangs forever instead of failing with exit 1. `dump.StdoutPipe()` leaves the read end of the pipe open in the guard process for as long as `dump.Wait()` has not run; once `restore` has exited nothing reads that pipe, so `pg_dump` (the `docker exec` client) blocks on a full pipe buffer and never gets the SIGPIPE the bash pipeline gave it, and `dump.Wait()` waits on it for ever. The bash it replaces exits 1 with "copy into flow_<name>_live failed" in the same situation. Any real `flow` dump is far larger than the 64 KB pipe buffer.

+// pipefail: true only when both ends succeed.
+func (l *lsc) copyStore() bool {
+	dump := l.pg("pg_dump", "-U", "flow", "--no-owner", "--no-acl", "flow")
+	restore := l.pg("psql", "-q", "-v", "ON_ERROR_STOP=1", "-U", "flow", "-d", l.db)
+	pipe, err := dump.StdoutPipe()
+	if err != nil {
+		return false
+	}
+	// Both ends write the one stderr, as the bash pipeline's shared fd did;
+	// a writer that is not a file is copied into by a goroutine per end.
+	shared := &lscLockedWriter{w: l.stderr}
+	dump.Stderr, restore.Stdin, restore.Stderr = shared, pipe, shared
+	if err := dump.Start(); err != nil {
+		return false
+	}
+	restoreErr := restore.Run()
+	dumpErr := dump.Wait()
+	return restoreErr == nil && dumpErr == nil

Why picked

1. Defect class: a port reproduces what the original does when everything works, but not what it does when a step fails (an exit code, a peer dying early, a timeout, a signal), because the port's tests are copied from the original's harness, which never drove that failure. 2. The Testing principles cover tests written first, asserting behaviour, determinism and error-path fixes driven by their real trigger (the quoted before paragraph), and the Robustness section covers swallowed errors and unbounded external calls. No rule says that rewriting existing code must preserve, and test, each way the original fails. Here the task said to port every case of scripts/test-live-store-copy.sh, which had no early-psql case, so the Go copyStore hung forever where the bash pipeline exited 1. 3. It generalises to every rewrite of working code: shell to Go (this repository has ported dozens of guards this way and ported three more scripts in this run), one HTTP or DB client library for another, a pipeline into spawned processes, a sync call into an async one. In each, the old suite pins only the failures someone once wrote a test for. 4. It states a principle (behaviour parity includes the failure paths, read from the original's code rather than from its old tests), not a rule about pipes or SIGPIPE.

Before

**An error-path fix is tested against its real trigger.** A test that hands the fixed handler a
payload the real backend never sends on that path — a bare `403` where every real one carries an
error code — proves nothing about reachability: a global interceptor, a client-wide handler for
that status or code, can take the real response first and leave the local handler dead while its
test stays green (KAN-691). Before the test is written, trace the real response through every
interceptor to the handler, and drive the test or reproducer with that real response, end to end.

After

**An error-path fix is tested against its real trigger.** A test that hands the fixed handler a
payload the real backend never sends on that path — a bare `403` where every real one carries an
error code — proves nothing about reachability: a global interceptor, a client-wide handler for
that status or code, can take the real response first and leave the local handler dead while its
test stays green. Before the test is written, trace the real response through every
interceptor to the handler, and drive the test or reproducer with that real response, end to end.

**A port keeps every way its original fails.** Code rewritten into another language, library or
process model keeps not only the original's result on the happy path but each failure it had — its
exit code when a step fails, a peer that dies early, a timeout, a signal. Before the port is
written, list how the original fails from its code, not only from its old tests: a harness ported
case for case inherits its gaps. The port's tests drive each of those failures and assert the
original's outcome, bounded so a hang fails.
