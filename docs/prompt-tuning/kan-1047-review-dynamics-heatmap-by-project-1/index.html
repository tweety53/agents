Why picked

1. Defect class: a capture test records a state other than the one it names — the state's interactions run after its screenshot, or transient pointer state is left on the page. 2. No rule covers it for implementers: the capture rules ('A capture reached through a click also asserts the state it clicked into, and parks the pointer before it is taken', visual-verify-verifier.md:49) reach only the verifier; the implementer instructions for capture tasks say only how to get a stack (the quoted One stack for the verification tasks paragraph), and a grep of implement.md, sdd-dispatch.md and engineering-principles.md for pointer, mouse.move, hover ink and park finds nothing. 3. It generalises: two separate implementer dispatches in this run hit it — Task 4 (0470e14b) picked Projects and Task size after its last screenshot, costing visual round 2; Task 5 (bde84fe0) left the pointer on Big, costing round 3 — and every planned capture task and in-run visual fix task is written by an implementer, not the verifier. 4. It is not patch accretion: one set of capture rules for whoever writes a capture, a pointer to the verifier's existing rules rather than a copy.
