Why picked

1. Defect class: a test's blocking wait (reading a child's output, receiving from a channel, waiting on a process or lock) carries no deadline of its own, so a regression turns the test into a hang that only the runner's global timeout ends, minutes later and with no message naming the wait. 2. The Testing principles list names a sleep used for synchronisation and order- or clock-dependent results, and the robustness principle names an external call with no timeout, but nothing names a test's own unbounded wait; the quoted before paragraph is the whole violation list for tests. 3. It generalises to every test of concurrency, signals, subprocesses, servers, queues and streams in any language (Go's go test 10m default, JUnit with no timeout, Jest overrides), and here the mutation reviewer had to find it because the implementer bounded the final Wait with 5s but left the two output reads unbounded. 4. It states a principle (every blocking wait in a test is bounded, so a failure fails), not a special case of signal tests.
