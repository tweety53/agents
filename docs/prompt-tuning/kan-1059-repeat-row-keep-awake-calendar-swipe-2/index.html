Defect class

Code that intercepts a stream, callback or channel to change how one kind of event is handled forwards only the kinds it handles, silently dropping every other kind the original consumer relied on.

Finding

Held-back interaction source drops Hover/Focus, so the day cell lost its hover and focus layers: `clickable(interactionSource = presses, indication = null)` routes every interaction into `rememberHeldBackPresses`, whose `when` forwards only Press, Release and Cancel.

+/** How long a day's press waits before it draws — Android's tap timeout, which web Compose does not apply (KAN-1059). */
+private const val PRESS_HOLD_BACK_MS = 100L
+
+/**
+ * [presses] as the day cell's indication sees them (KAN-1059, `swipe-equals-arrows`): a press draws only
+ * once held [PRESS_HOLD_BACK_MS], so a calendar swipe — which cancels the press once it passes touch slop —
+ * never draws the day under the finger pressed. A tap released sooner still flashes, press and release at
+ * once; a press cancelled sooner draws nothing. This is what Compose does under a scrollable container on
+ * Android, where the delay is the tap timeout; on web it is zero.
+ */
+@Composable
+private fun rememberHeldBackPresses(presses: MutableInteractionSource): MutableInteractionSource {
+    val shown = remember { MutableInteractionSource() }
+    LaunchedEffect(presses) {
+        var pending: Job? = null
+        val drawn = mutableMapOf<PressInteraction.Press, PressInteraction.Press>()
+        presses.interactions.collect { interaction ->
+            when (interaction) {
+                is PressInteraction.Press -> {
+                    pending =
+                        launch {
+                            delay(PRESS_HOLD_BACK_MS)
+                            val press = PressInteraction.Press(interaction.pressPosition)
+                            drawn[interaction] = press
+                            shown.emit(press)
+                        }
+                }
+
+                is PressInteraction.Release -> {
+                    pending?.cancel()
+                    val press =
+                        drawn.remove(interaction.press) ?: PressInteraction.Press(interaction.press.pressPosition).also { shown.emit(it) }
+                    shown.emit(PressInteraction.Release(press))
+                }
+
+                is PressInteraction.Cancel -> {
+                    pending?.cancel()
+                    drawn.remove(interaction.press)?.let { shown.emit(PressInteraction.Cancel(it)) }
+                }
+            }
+        }
+    }
+    return shown
+}

Why picked

1. Defect class: an interposed handler written for one event kind swallows the others. 2. The quoted Least Astonishment violation list is the nearest rule and names no interposition case; nothing in implement.md or sdd-dispatch.md covers pass-through. 3. It applies to every middleware, interceptor, event filter, decorator, proxy and when/switch over a sealed event type without a forwarding branch, in any language and layer. 4. It states a principle (pass through what you do not mean to change), not a rule about Compose interactions.
