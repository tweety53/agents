# kan-1059 self-review: 1a's and 1b's begin refusals, 1c's gate rewording and 1f's Class.method rule are new requirements, not paraphrases.
**An item no change to the tree can finish** — a verify failure that does not recur in at most 5 single-worker, isolated re-runs of the test alone (or with the one test whose leftover state it reads), the run count stated — a load re-run only under run-capped.sh (`skills/flow/verify-fix-loop.md`); a verdict the guard reaches over a report line that names a passing spec — is recorded as a guard false positive per **A verdict the operator calls structural** below, its `-reason` carrying that run count, and the run continues to the landing route.
**An item no change to the tree can finish** — a verdict the guard reaches over a report line that names a passing spec — is recorded as a guard false positive per **A verdict the operator calls structural** below, its `-reason` naming that spec's passing run, and the run continues to the landing route.
A fix commit's `Flow-Key:` trailer names that same fix round, and `flow record dispatch begin` refuses the re-review's reviewer rows while a commit authored since the reviewed round began carries a `Flow-Key: panel-fix-<k>` trailer of any other round (kan-1059 self-review, 1a).
A token written `Class.method` is found when both its segments are, so a test may be named as the pipeline's `fix-mutation:` lines name it (kan-1059 self-review, 1f).
`flow record dispatch begin` refuses that re-review's reviewer rows while the reviewed round holds a fixed Critical or Important finding and no fix-mutation row at the fix round (kan-1059 self-review, 1b).
