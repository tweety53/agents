# Intended rule edits of the self-review fixes (tasks 2-5).
Before `verify`, `check-dev-stack-fresh.sh <canonical-worktree>` exit 1 restarts the stack by that section's start rule, and a failed restart is reported and stops the step; exit 0 or 2 proceeds.
When the change's diff touches a `## visual verification` `ui paths` glob (`git -C <worktree> diff --name-only <merge-base>..HEAD | check-visual-trigger.sh <worktree>` exits 0 for any worktree in the resolved set, or the `--repo` run step 2 of **Visual verification** (`skills/flow/verify-and-handoff.md`) adds exits 0 for any other worktree, its merge base from this run's working notes; no exit 0 from either skips this run) and `decision.json` does not record `visual.verify` `skipped`, the list ends with that section's `verify` run whole — `<specs>` empty, every capture — against the canonical worktree's stack, under the stack rules of **One stack for the verification tasks** below, so a capture a shared-component change moved fails here rather than at `flow.verify`.
`verify` runs from the resolved regression checkout (the project root when none is declared), after the section's `setup` row when the toolchain is missing.
A reproducer never `cd`s — it runs each tool against its directory with `go -C`, `make -C` or `npm --prefix` and names every file as `$PWD/<path>` — and makes its edit through a patch file or a fixed-string replacement, never through shell quoting nested inside another quoted string (kan-1047: an EXIT trap restoring a relative path after `cd stats` left a live mutant, and nested single quotes in a `sed` never applied the edit).
Before the list, on a change whose diff touches a `ui paths` glob, `check-dev-stack-fresh.sh <canonical-worktree>` exit 1 restarts the stack by that section's start rule, and a failed restart is reported and stops the step; exit 0 or 2 proceeds.
The file draws the proposed page alone — no caption, note or screenshot beside it — since `flow.visual-verify` renders the whole file as the capture's frame; a note to the operator goes in the message (kan-1047: a caption over a JPEG of the live page never paired with a capture).
The section's `setup` row runs before the list when the toolchain is missing.
`check-plan-shape.sh` F22 refuses a plan whose design cites the prototype and whose tasks touch a `ui paths` glob while no task's `**Files:**` names a file under `screenshots` (kan-1047).
`run-verify-list.sh`'s `test` list ends with that section's `verify` run whole — `<specs>` empty, every capture — when its own worktree's diff from its base branch touches a `ui paths` glob and `decision.json` does not record `visual.verify` `skipped`, its header canonical for the rest, so a capture a shared-component change moved fails here rather than at `flow.verify`.
On a change whose diff touches `ui paths`, the `test` group also ends with the project's `## visual verification` `verify` row, the full suite, run from the change's worktree of the `regression checkout` repo, unless decision.json records the visual verify skipped.
