**Goal:** Rework Trend over time (KAN-1051) to answer "Is a finished change getting cheaper as flow changes?" — whole-life cost per finished change by Wednesday week, with Period, Command and Project chips, three tiles, a median/mean chart with flow-changes-landed bars and a By week table — and fix harvest so spend between two stage windows is attributed, with a once-only back-fill of what the old rule dropped.

**Architecture:** `harvest.Window` gains the change's finish instant; `Attributor.Attribute` falls back to the last-begun window when no window contains a record. A one-shot `Watcher.BackfillStageGaps`, run by `flowd` before the watcher's first cycle, re-reads each transcript's already-harvested bytes, keeps only fallback-placed records and commits their deltas in one transaction with a `harvest_backfills` marker. `TrendOverTime` becomes `TrendFinishedChanges`, one row per finished change; the view owns its chip state and computes every figure client-side from one request.

**Tech Stack:** Go (`stats/internal/harvest`, `stats/internal/store`, `stats/internal/api`, `stats/cmd`), React/TypeScript (`stats/web`), vitest, Playwright.

**Spec:** `design.md` beside this file, and the approved prototype `.superpowers/sdd/trend-prototype.html` in the worktree (published https://claude.ai/artifact/DD57gkG9bSht6o2EuD3kLj) — canonical for markup, copy, column order, number formats, chart geometry and the `tr-*` rules.
