# Intended rewording: run-verify-list.sh now ends rows blocked/skipped itself.
A group that exited non-zero records no `end`; once its one inline re-run is decided, the parent ends the row itself, `-outcome completed` when the re-run passed, or `-outcome blocked -cause <cause>` when a command failed twice — `test-failure` for a command of the branch that failed twice, `environment` where the environment itself failed twice (a missing build prerequisite).
`run-verify-list.sh` records the row itself, never the parent by hand: both groups are run with the same five trailing arguments, and each records `begin` before its first command and `end -outcome completed` after its last when its list exited 0.
A verify re-run after a new code commit passes a key no earlier verify row of the change used — `verify-<k>`, `<k>` counting from 2, suffixed as above — because the store keeps a reused key's first `startedAt`, and a row started before the commit never covers it (kan-1037).
Never symlink a shared `node_modules` into a copy: the copy's own `npm ci` installs one, and over a symlink it empties the shared directory (kan-1037) — `<agents repo>/stats/Makefile` refuses to run it there.
Once the one inline re-run is decided, a passing re-run ends a fresh row `-outcome completed`, and a command that failed twice for a missing build prerequisite is ended `-outcome blocked -cause environment` by the parent.
`run-verify-list.sh` records the row itself, never the parent by hand: both groups are run with the same five trailing arguments, and each group records `begin` before its first command and ends the row itself — `-outcome completed` when its list exited 0, `-outcome skipped` when every command of a test group was cache-skipped, `-outcome blocked -cause test-failure` when its list exited non-zero.
