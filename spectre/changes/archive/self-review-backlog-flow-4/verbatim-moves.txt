# Sentences this change adds on purpose — KAN-691 (engineering-principles.md), KAN-698 (plan-provenance.md).
\## A prerequisite is measured on the worktree's own HEAD
**An error-path fix is tested against its real trigger.
A plan that rests on another change being present — "KAN-361 is merged before task 7" — measures it in the worktree the change is implemented in, never against a remote branch: `git -C <worktree> merge-base --is-ancestor <prerequisite sha> HEAD`, its `measured:` comment naming that worktree's HEAD as the ref.
A remote branch carrying the prerequisite says nothing about a worktree based before it (KAN-698: confirmed against `origin/develop` while the backend worktree's HEAD lacked KAN-361, so the feature was silently absent on the stack).
A test that hands the fixed handler a payload the real backend never sends on that path — a bare `403` where every real one carries an error code — proves nothing about reachability: a global interceptor, a client-wide handler for that status or code, can take the real response first and leave the local handler dead while its test stays green (KAN-691).
Before the test is written, trace the real response through every interceptor to the handler, and drive the test or reproducer with that real response, end to end.
The first step of every task that depends on the prerequisite runs the same check in its own worktree; an exit 1 is a stale base the implementer reports and never builds past — rebasing the worktree is the operator's call.
