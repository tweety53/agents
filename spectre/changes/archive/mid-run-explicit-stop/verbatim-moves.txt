# Sentences mid-run-explicit-stop rewords on purpose: a mid-run operator message is not a stop by default, and an explicit stop instruction ends the run.
**An operator message that arrives mid-run is never a stop.
A question, an aside or a side request the operator sends while a run is executing — about the run, the change or anything else — is answered or done in the run's own output, and the same turn then continues into the run's next step.
The run ends only where this file names a stop; an operator message that is not itself an answer to the run's own ask names none (kan-1033: the parent closed the review panel, answered two mid-run questions and filed a requested ticket, then ended the turn with verify still to run).
**An explicit instruction to stop is the one exception** — "stop", "pause", "wait for me", "don't continue": the run finishes the step in flight, waits for every child it launched, answers what the message asked, and ends the turn at the state it reached, naming the next step and `/flow <name>` to resume.
