# kan-1052-rework-the-stage-leaderboard-dashboard

> **Execution:** `/flow` implements this plan. Mark a task's own checkbox when
> `check-task-commit-fields.sh` passes on that task's commit.
> **Relocation:** no
> **Design shape:** plan-mode

**Goal:** Rework the Stage leaderboard (KAN-1052) to answer "Which stages take the most of the spend, and which are growing?": chip filters, Spend / Top 3 / Biggest riser tiles, a ranked table with Share, growth and an Other row, plain-English stage names — over an endpoint that returns every costed stage and each project's spend.

**Architecture:** `StageLeaderboard` drops its row cap; a new `StageLeaderboardProjects` store method fills a `projects` field on the stage-leaderboard response. The view owns its period/project/command state, fetches the chosen window and the previous one through `useStatsView`, and renders the prototype's markup with the existing `lb-*` rules plus `sl-*` rules copied from the prototype. Playwright captures move to their own spec; the dashboard-bar control tests move to the Reviewers view.

**Tech Stack:** Go (`stats/internal/store`, `stats/internal/api`), React/TypeScript (`stats/web`), vitest, Playwright.

**Spec:** `design.md` beside this file, and the approved prototype `.superpowers/sdd/stage-leaderboard-prototype.html` in the worktree (published https://claude.ai/artifact/MnKPxwCnnSsspu4ULnePfs, version 3) — canonical for markup, copy, column order, number formats and the `sl-*` rules.
