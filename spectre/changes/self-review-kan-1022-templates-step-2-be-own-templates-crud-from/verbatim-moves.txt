# Sentences this change adds on purpose — the kan-1022 self-review pass: steps 8–10 beside a wire contract (visual-verify-verifier.md), flowBase worktrees and the voided rerun (visual-verify.md), the reproducer check and the mutation tree (review-panel.md).
**A change whose worktree records a flowBase gets a worktree in every `## apps` repository the set holds none in, the same way** — the `kickoff-worktree.sh --from` call and its merge-order record, before the checks below — so the stack serves `<base>`'s build, never a main checkout on the default branch: kan-1022's stack served the `develop` frontend to a change based on feature/templates, and 28 specs failed on it.
**A reproducer's check reads the defect's behaviour, never one fix route's text**: it runs the path the defect takes, or reads the defect's own code, so any fix that removes the defect turns it to defect not demonstrated — a grep for one fix's call, or for call-site text a fix leaves unchanged, makes the parent re-author it (kan-1022's F7 grepped `catalog.byKeys(keys)`).
**An environment cure that changes what the stack serves — a served root switched, a worktree added to the set — voids every earlier pass**, so the next re-dispatch runs unscoped; `check-visual-verify-dispatched.sh` reports a newest verifier whose report re-ran failed specs under a `-diff-base` other than the verifier row before it as MISSING (kan-1022: a rerun of 19 failed specs left 76 never run against the served feature/templates frontend).
Its tree is `$PWD`, the worktree `run-reproducer.sh` passes — never the slot's throwaway copy it was authored in, which is gone once the dispatch closes (kan-1022's F8 pointed at that copy and demonstrated nothing).
With a `wire contract:` line the dispatch names no view, so steps 8, 9 and 10 read n/a — wire contract, no view drawn — never `done` over a capture that never ran (kan-1022's self-review).
